# Codex Mobile Bridge：DSH 接入插件

将当前电脑上的 DeepSeek Harness 档案连接到 Bridge，沿用原会话、模型、权限和工作目录。插件只监听本机回环地址，不向局域网开放端口。

## 安装和绑定

1. 可在支持的 Harness 插件市场中安装 `dsh-codex-mobile-bridge`；当前为本地测试包，尚未上架。也可以解压插件包，保留完整文件夹。在兼容 Harness 核心的客户端插件管理中选择本地安装，选择解压后的文件夹，按客户端提示重新加载。
2. 在 Bridge 的“添加接入 → DSH / 自定义 Harness”中展开“第三方客户端：手动安装与绑定”，选择该档案生成的 `binding.json` 并绑定。
3. 文件位于 **Harness 数据目录 / profiles / 当前档案名 / codex-mobile-bridge / binding.json**。数据目录和当前档案以客户端设置为准；也可使用“扫描 Harness 数据目录”选择该目录，再选择要绑定的档案。扫描只读取插件生成的身份文件，不依赖应用名称，不会自动绑定或启动会话。
4. 开启 DSH 接入。以后先打开该客户端，再启动网关即可；网关不会代替第三方客户端启动或退出应用。

使用原生 CLI 安装时，在对应核心的环境中运行：

```sh
dsh plugin --profile web add file:/绝对路径/dsh-codex-mobile-bridge
```

将 `web` 替换为实际档案名；不要将插件重复安装到同一运行时。官方 DSH Desktop 仍使用 Bridge 已有的一键安装，无需手动安装此包。

## 使用和移除

- 一个网关同时绑定一个 DSH 接入。切换前先“仅停用手机接入”，再选择新的绑定文件。这样不会终止电脑上的任务。
- 账号和 API 在第三方客户端内配置；Bridge 读取模型和账号状态，不改写第三方客户端的认证配置。
- “解除绑定”只清除该网关的选择。卸载插件请使用客户端插件管理；卸载不会删除聊天。
- `connection.json` 是本机连接凭据，不能发送给他人或放进发布包。`binding.json` 只在同一台电脑上使用，不能用于跨电脑连接。
- 聊天、审批、通知和归档依赖所用 Harness 核心提供相应接口。通知沿用 Bridge 已有通知设置。归档仍需要二次确认，先确认停止目标任务，再调用原生归档；失败不会伪装成功。

本包不包含第三方客户端、Harness 核心、账号凭据或聊天数据。协议实现改编来源及许可见 `LICENSE.coding-mobile`。

## 兼容性

这是面向 Harness 核心的通用插件，不限定 Electron、Tauri 或客户端名称。核心需提供 `profileContext` 和本包 `host.mjs` 所需的服务接口；仅有相似名称或 Web 页面并不代表兼容。当前实机验证：macOS arm64、DSH Tauri v0.25.0、`@deepseek-ai/dsh` 0.2.1-rc.2。其他版本与第三方客户端需验证后才能标为支持。网关绑定时核对插件版本并进行认证握手；仅扫描到档案不代表已连接。


## 包格式与协议

网关导出两个无凭据包：ZIP 用于解压后选择本地目录，标准 `.tgz` 用于支持 npm 包的安装入口。包中已包含 `host.mjs` 和许可证，无需安装时编译，也没有安装脚本。发布时应使用导出的完整包，不能直接发布源码中的 `plugin/` 目录。官方插件市场是用户添加的索引源，并非默认内置商店；当前没有公开索引或 npm 发布。

本版声明 `engines.dsh: 0.2.1-rc.2`，对应已验证核心。不同客户端只要使用该核心并保留必需服务，均可作为验证候选；客户端品牌、窗口框架和程序名不参与绑定。暂不向未验证的核心版本放宽范围。

独立插件版本为 `0.2.x`，网关支持线协议 `protocol: 1`、消息修订 `revision: 9`。兼容补丁不再要求与网关内置文件逐字节相同；绑定文件、安装清单与已认证的运行中插件必须声明一致。升级后需要在原客户端重新加载；若安装路径改变，重新选择绑定文件。未知协议、版本系列或运行中旧代码会明确拒绝，写操作不会尝试兼容性降级。旧 `0.1.0` 包仅保留已知源文件哈希与运行修订核验。

绑定预览显示实际 profile、数据目录和插件版本。确认后再次核对实例 ID，避免预览期间切换档案而绑定到其他实例。安装来源仍需由用户信任；协议握手不是插件签名或安全审计。
