# Windows ChatGPT 与 WSL Codex

同一个 Windows 网关可以分别接入 ChatGPT 内的 Codex/Work 和 WSL 终端里的 Codex。两个入口的历史、草稿、附件、操作记录与接入说明分别保存。其他电脑接入不属于本轮实现。

## 连接 WSL

1. 在电脑上正常启动 WSL 和 Codex 终端。
2. 使用更新后的源码启动网关，在聊天列表点击 **扫描 WSL**。
3. 核对发行版和用户，点击对应入口的 **连接**。
4. 在 **全部 Codex 入口** 下拉框中选择桌面或 WSL，也可合并查看列表。

扫描只检查正在运行的发行版，不安装 Codex、不启动新的执行器，也不自动启用发现的入口。每次执行 WSL 辅助请求前重新核验运行状态；已停止或无法确认状态时保持离线。

当前扫描发现的是发行版默认用户的 Codex 目录，以及该用户正在运行的共享服务使用的自定义 `CODEX_HOME`。不会把 Windows 的配置和环境变量当成 WSL 的配置。与桌面共用同一已识别数据目录的入口不能重复登记。

**历史可读不代表可以控制。** 普通 CLI 历史可以查看；发送、补充、停止和模型设置要求线程仍在原共享服务中加载，并报告允许直接输入。未加载的聊天需要先在原终端打开。旧 CLI、`--no-daemon` 或缺少相应控制能力的入口保持只读，Bridge 不为它另起执行器。

用户打开或操作已加载线程时，Bridge 通过同一服务的原生订阅接收实时事件和审批。订阅不传入模型、认证、提供商、目录或权限覆盖。后台读取不调用线程恢复或启动接口。

## Magpie

- Windows 与 WSL 分别读取各自的接入。查看 WSL 接入时不会显示或切换 Windows 的账号。
- 检测到 Magpie 配置时启用外部管理保护。也可在 Bridge 桌面端的账号面板选择 **由 Magpie 等外部工具管理**。
- Bridge 不将该接入自动转换为 `bridge_api`，不替换认证，不移除 Magpie 提供商和模型目录。
- 模型列表由对应 Codex 原生运行时读取，保留 Magpie 的模型和路由组 ID。查询失败不会切回官方或改模型。
- 接入切换继续在 Magpie 或原 WSL 环境完成。聊天中的模型设置只作用于允许修改的原线程，不重写全局提供商。
- 如果切换或恢复期间发现外部配置变化，保留现场并阻止覆盖恢复。

检测到历史保留的 Magpie 配置表时也会保守地保护配置，避免破坏依赖该提供商的旧聊天。接入管理模式不是“强制覆盖外部配置”的开关。

## 本轮能力

| 能力 | WSL 入口 |
| --- | --- |
| 发现、搜索、归档历史展示、按入口筛选 | 支持 |
| 当前已加载线程的发送、补充、停止 | 支持；操作前重新读取原生状态 |
| 原线程模型与推理强度设置 | 支持；不改变提供商、认证、工作目录或权限 |
| 原生审批及结构化问题 | 支持原请求允许的范围；过期或旧连接请求不能再次授权 |
| 工作区文件、Git、附件上传与预览、下载 | 通过 WSL 中的共享文件边界实现 |
| 后台通知、网关排队、独立终端、侧边聊天、Goal、计划/权限模式切换、Skill 选择 | 本轮禁用，避免套用桌面专用接口 |
| 从手机新建 WSL 聊天 | 本轮不提供；先在原终端创建，再从列表打开 |

关闭 WSL 接入只关闭 Bridge 自己的连接，不退出 Codex、不停止原任务。断线期间可能已提交的写入保留为结果待核对，不自动重发。

本机实测组合是 WSL 2 / Ubuntu-22.04、CLI 0.162.1 和共享服务 0.163.0。其他版本按实际能力判断，不能把目录存在视为控制能力验证通过。详细证据与测试边界见[验证记录](architecture/windows-wsl-validation.md)。
