# Agent Note: 文件阅读字号独立于聊天和终端

Status: implemented

## Problem

文件正文和源码没有统一字号控制，聊天和终端字号不能表达文件阅读偏好。

## Decision

文件预览工具栏沿用终端的减小、数值、增大控制形式，独立保存 bridge-file-font-size，范围 6–24px，默认 14px。所有打开及以后打开的文本文件共享字号；CSS 变量只作用于文件阅读正文、源码和 Markdown 代码块。源码行与行号仍在同一字号和 Grid 行中。

标签关闭和工作区清理解除控制注册。HTML 源码显示字号，隔离页面预览将同一偏好显示为相对默认值的缩放百分比，仅缩放外层 iframe 并反向补偿其视口尺寸，不读取沙箱 DOM、不改变原文或消息契约；PDF 和图片不显示此控制，保留自身真实缩放。窗口 storage 事件同步文件字号，不读写聊天或终端偏好。

## Existing-note audit

现有源码视图笔记保留独立行号与精确复制决定；终端字号实现是交互参考，本次不修改终端行为。检索活跃文件笔记没有全局文件字号决定。

## Alternatives considered

- 共用聊天或终端字号：省一份状态，但不同阅读场景互相干扰。
- 用 CSS transform 缩放全部文件预览：可覆盖图片和 HTML，但不会正确重排正文，且混淆字体与 PDF、图片缩放。
- 向 HTML 沙箱新增缩放通信：可调整页面预览，但增加独立协议；外层 iframe 缩放保持既有来源、CSP 和沙箱边界。

## Consequences

字号变化触发文本自然重排，包括换行源码和行号。PDF 和图片保留原来的大小行为；HTML 预览以真实页面缩放呈现同一全局偏好。浏览器拒绝本地存储时，本页内仍能调节，重载恢复默认值。
