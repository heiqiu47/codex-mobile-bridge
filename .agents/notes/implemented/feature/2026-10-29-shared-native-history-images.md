# Agent Note: 共用原生历史图片引用与按需预览

Status: implemented

## 问题

Claude 与 DSH 的历史解析把图片压成文字占位，远程发送后的图片无法重新查看。把图片数据直接加入轮询会重复传输大图，也会扩大浏览器缓存及跨账号泄漏风险。

## 决策

适配器只从原生消息生成图片引用，包含事件和内容块身份。共享 `HistoryImages` 把引用绑定到 provider 与 session，公开接口只返回不透明标识，内部引用不进入浏览器。注册表有 4096 项上限；刷新聊天可以重建引用。预览时再次查证原生历史中的所属关系，不从 URL 或任意文件路径加载图片，不启动会话。

读取出的 base64 在共享层校验大小和真实光栅格式，单图沿用上传的 20 MiB 限制。预览响应保留认证和原有 Host/Origin 检查，并使用私有、不落浏览器缓存的响应。会话不存在、图片删除、引用淘汰、原生接口缺失均不回退到其他会话或路径。

Claude Desktop 连接器增加按事件与块序号读取原图的只读操作。CLI/SSH/WSL 用现有会话路径身份读取对应 JSONL 事件；远端仅嵌入共用读取函数，不要求安装 Bridge。DSH 独立插件使用原生冷读及附件服务，Bridge 依照固定提交同步源码，未推送插件或主仓库。

`renderChatAttachments` 共用原有 Codex 附件标记、样式和图片查看器。Codex 的路由及显示规则不变，其他客户端只提供自己的认证预览路由。历史分页和消息节点复用不因图片重新生成正文。

## 备选方案

随历史返回 base64 的实现更简单，但两秒轮询会重复传图，因此使用按需预览。仅匹配上传缓存可少改原生接口，但图片可能被原生客户端规范化、历史缓存也可能过期，无法可靠证明对应关系，因此直接依据原生消息身份读取。

## 测试

共享图片与 Claude/CLI/远端/资源清单相关测试 118 项通过。单独连接器验证原始块序号、历史脱敏、按需读取和不存在引用。桌面会话界面测试 165 项通过，覆盖刷新后节点复用与提供方路由隔离。独立 DSH 插件 4 项测试和本地打包通过。浏览器及最终真实安装的结果另记录在集成验收中。

## 影响

历史列表不携带图片字节，滚动到图片时才请求；代价是原生客户端不可用时不能预览尚未加载的图片。原生接口需支持 base64 光栅内容或 DSH 附件服务，不自动读取外部 URL、SVG 或未经证实的路径。

历史决策核对：[CLI 附件](2026-10-14-claude-cli-attachments.md)保留发送与文件范围规则，与本篇仅在历史查看部分重叠；[独立插件源码边界](../architecture/2026-10-29-dsh-plugin-source-boundary.md)继续约束固定提交同步。Markdown 文件显示记录保持原决定，无完全吸收或应拒绝的记录。

官方接入的旧 revision 9 源码指纹（含 LF/CRLF）继续识别为兼容版本，不因新增只读图片操作强制中断旧聊天。历史图片预览需要更新运行中的插件；扫描不会静默覆盖旧插件。迁移回归核验已知旧指纹、当前两种换行及未知修改拒绝，相关 56 项测试通过。

实机发现上一轮 Test 的 host 与基线 `3183f3b` 完全一致，但旧迁移夹具固定的是更早版本指纹。补录基线实际文件的 LF/CRLF 摘要后保持精确识别，不放宽为任意 revision 9 源码。未知修改仍拒绝。

Mac 实机加载新 Claude 连接器时，文件预览分区 `Claude-3p/Partitions/cowork-file-preview` 被识别为第二个 profile，导致回退到默认目录并误报未启用开发者模式。原生目录发现仅在父 profile 也有独立打开存储证据时排除其 `Partitions/<name>` 子目录；真正的多根目录冲突仍不猜测。回归先复现错误回退，再验证预览分区与多根冲突。没有采用写入默认目录开发者设置的方式，因为那会改变错误账号目录的权限，且不能解决识别原因。
