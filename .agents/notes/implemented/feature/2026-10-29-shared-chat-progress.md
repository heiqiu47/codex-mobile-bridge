# Agent Note: 共用原生任务状态提示

Status: implemented

## 问题

Claude 与 DSH 的历史接口可能在回复持久化后才返回正文。发送回执提示消失后，聊天正文缺少持续的工作指示，难以区分等待生成、等待审批和连接失效。后续 Agent 接入也需要同一行为。

## 决策

`web/features/chat/activity.js` 提供共享的 `renderChatProgress`。Codex 和桌面会话页传入运行、审批、失败、连接与数据新鲜度，组件不按客户端名称选择行为。审批优先于运行，新任务运行优先于上一轮失败；读取失败显示状态暂不可用，空闲时隐藏工作提示。

共享组件只呈现已有原生证据，不启动会话、不改变发送流程、不产生通知。Codex 离线历史页面仍不显示额外工作提示。适配器继续解释原生状态，界面不能从错误文案猜测任务是否活跃。

## 备选方案

分别添加动画实现较快，但会复制状态优先级和断线处理，因此共用现有聊天功能目录。将最终正文逐字播放能制造流式外观，但没有实时进度证据，因此不采用。

原生增量是独立后续工作：已查证 DSH 的 `agent/assistant-stream` 和 Claude CLI 部分消息事件，尚未实现增量协议；本改动不宣称解决逐字输出。

## 测试

`tests/desktop-sessions-ui.test.cjs` 覆盖运行、审批、断线、失败、完成、切换聊天及未知 Agent 名称。`tests/cli-access-ui.test.cjs` 加载真实共享组件检查 Codex 历史与恢复行为。两份测试共 178 项通过。

完整前端回归 1298 项通过、1 项跳过；模块边界及 90 篇笔记的结构、相对链接校验通过。浏览器与真实客户端验收属于后续集成阶段，本记录不将单元测试当作实机验证。

## 影响

聊天界面共用任务状态规则，不增加请求或计时器。状态更新仍受原有轮询和网络延迟影响。

活跃笔记检索：`SessionActivity`、工作状态、增量、任务状态命中的 iOS 前台通知与确认归档记录分别约束通知及写操作，与本决定不重复，保留原记录。
