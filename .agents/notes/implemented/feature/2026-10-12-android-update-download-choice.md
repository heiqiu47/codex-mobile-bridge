# Agent Note: Android 更新下载方式由用户选择

Status: implemented

## 问题

用户实测时，点击「下载并安装」后自动进入电脑下载，无法明确决定使用哪一端的网络。用户可能已知手机无法访问 GitHub，也可能希望仅使用手机网络，不应由一次请求失败代替其选择。

## 决策

点击「下载并安装」后显示两个操作：手机直接从 GitHub 下载、电脑从 GitHub 下载后传到手机。用户点选后才启动相应下载；取消不发起 APK 下载或网关准备。每次重新下载都可选择，不引入持久默认选项。

手机直下载失败后不自动使用电脑；下载卡片提供「重新选择」以及「GitHub ↗」入口。后者用外部浏览器打开当前已检测到版本的官方 APK 直链，由浏览器负责下载；即使原任务来自电脑，也不向浏览器传递网关地址或凭据。重选同一路径时可复用可续传任务，换路径时建立对应的新任务。暂停后的继续仍沿用已选路径。选择电脑时使用当前保存的电脑连接，继续核对登录、版本、大小和摘要。

版本查询仍允许直接查询失败后由电脑查询，避免手机无法发现更新。查询成功与哪一端负责下载是两个独立决定。网关来源限制、缓存、认证、中继及安装恢复沿用 [网关协助更新记录](2026-10-12-gateway-assisted-android-update.md) 和 [安装交接记录](../bug-fix/2026-10-12-android-update-handoff.md)。

## 备选方案

- **保留自动回退**：操作步骤少，网络正常时用户不必关心来源。但不能满足用户明确选择网络路径的要求，也会让已知手机网络不通的用户先等一次失败。
- **选择手机后仍自动回退到电脑**：失败时能省一次操作，但所选路径的含义不清晰。失败后由用户重新选择，保留重试与浏览器入口。

## 测试

用独立局域网测试包检查选择前无 APK 请求、取消无下载、手机失败不触发电脑 APK 请求、电脑选择直接请求网关，以及下载失败后的重新选择。补充验证下载失败卡片的「GitHub ↗」由外部 Chrome 打开 APK 直链，确认后下载的文件摘要与测试包一致；该局域网结果不代表真实 GitHub 网络已验证。安装包和模拟器验证证据存于 `.tmp/pr32-gateway/`。用户已报告实测通过，授权合并源码；本次不编译 App 或发布新版本。

## 影响

用户可以直接选择可用网络，代价是下载前增加一次选择。电脑下载仍要求当前网关支持该功能且已登录；两端都不能访问 GitHub 时仍可能失败。此改动限于 Android 下载交互，不变更网关接口。

历史检索命中两篇相关记录，均为部分重叠：网关记录的下载自动回退部分被替代并互链，其来源、认证和缓存约束保留；安装交接记录的文件校验与恢复约束继续适用。无完全吸收或过时提案需要归档。
