# Agent Note: Android 电脑与聊天选项菜单

Status: implemented

## 问题

PR #95 改善 Android 右上角“电脑与聊天选项”的分组、配色与触摸区域。它基于较早主线，与本地已经实现的统一主题、会话菜单逐级返回及通知来源选择有重叠，直接覆盖 MainActivity 会丢失这些行为。

## 决策

保留作者 heiqiu47 的原始提交 `14f57269c55306d2cbd64a051afd20f847fb8214`，通过本地合并纳入。GatewayMenu 只负责原生浮层布局、颜色和操作呈现；仍调用原来的账号、收件箱、外观、设置、刷新与应用图标入口。Lucide 图标声明随 NOTICE 打包。

菜单优先读取经过当前 WebView、连接地址和代次核对的页面颜色；读取失败或格式无效时使用当前 App 主题 Context 的颜色。切换主题时关闭旧浮层，保留原 WebView、输入草稿及双向主题同步。页面导航、窗口配置变化、后台切换和清理页面均关闭浮层；旧异步回调不能重新打开它。

返回键先消费原生菜单，包括正在等待配色回调的菜单。没有原生菜单时继续沿用可取消的 HTML `cancel` 事件、会话菜单逐级返回和聊天返回路径，不恢复 PR 较早版本中直接 `dialog.close()` 的逻辑。通知来源偏好、接收器、权限、后台服务和账户配置不改动。

## 备选方案

- 保留系统 PopupMenu 能减少自有组件代码，但不能满足这次接受的页面配色和分组呈现，因此采用 PR 的独立组件，限制其职责。
- 直接用 Activity 默认 Context 构造最简单，但页面配色不可用时不能保证跟随用户显式选择的 App 主题，改用既有 `ui.context`。
- 只处理已显示菜单的返回键可减少分支，但配色和延迟显示期间仍可能继续打开菜单，因此待显示实例也消费此次返回。

## 验证

整合前移动 Node 61 项通过，整合后 62 项通过；完整前端 1,277 通过、1 项既有跳过。Chromium/WebKit 宽窄视口会话菜单 16 项通过。Android JVM/HTTP 验证四来源选择、在途回调失效、重新开启基线、接收恢复、权限与 URL 边界。

Android API 35 隔离模拟器运行生产 Activity 和 WebView，使用合成页面及连接，验证深浅色、自定义色、无效颜色回退、主题事件、同一 WebView 与草稿保留、系统 Back、待显示菜单取消、HTML 逐级 cancel、导航及后台关闭、应用图标切换、设置入口和四地址通知偏好保留。首次合成页没有设置 history URL，原生同源检查拒绝了配色回调；补齐夹具 URL 后通过，产品校验未放宽。截图是原生组件与合成页面验证，不冒充真实用户会话。

可复跑入口为 `scripts/test-android-gateway-menu.py`，要求显式指定可丢弃模拟器和 Test APK；会重置该模拟器 Test 的偏好，不可用于用户手机。Android APK 编译验签及 iOS 无签名编译通过。日志和安装包在 `.tmp/pr95-20261028/`，原生回归结果在 `.tmp/android-gateway-menu-tests/`；红米真机新菜单仍待用户体验。

## 影响

原生菜单跟随聊天页面配色，已有会话菜单、主题及通知渠道能力继续保留。代价是维护 PopupWindow 的显示时序和生命周期；目前颜色解析仅接受完整六位十六进制颜色，其他格式使用原生主题回退。本次不增加 iOS 对应新样式、不调整默认网关端口、不修改网关产品代码。
