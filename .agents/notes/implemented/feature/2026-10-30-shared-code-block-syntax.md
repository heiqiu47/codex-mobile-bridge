# Agent Note: 聊天代码块标注语言并复用源码高亮

Status: implemented

## 问题

手机聊天的代码块只有右侧复制按钮，Python 等代码缺少语言标签与颜色。文件预览已有本地 Prism，另引入高亮库或为不同客户端复制实现会增加资源和维护成本。

## 决策

`web/shared/code-syntax.js` 统一语言别名、展示名、体积限制与安全词元渲染。聊天依据 Markdown fence 的首个语言字段识别类型，左侧显示语言、右侧保留复制按钮；无标记或未知类型显示「纯文本」，不根据正文猜测。内联代码及完整 Mermaid 图表继续使用既有路径。文件预览保留扩展名选择、行号与原文复制，只复用有界分词。

沿用本地 PrismJS 1.30.0 和现有语言集合，不增加库或 CDN。小型共享助手随页面加载，约 36 KB 的 Prism 移入独立 `syntax` 懒加载组；纯文本和超限代码不请求它，多个代码块及文件预览共享一次加载。异步完成只着色仍在 DOM 内的代码节点，不重建消息、输入框或草稿；失败保留纯文本，不自动循环重试。浅深色词元样式上提共享文件。

超过 65,536 字符或 4,000 行不分词；高亮使用文本节点和 `span`，不把模型内容交给 HTML 解析。复制继续通过原有完整正文读取函数，不能从语言标签、着色 DOM 或截断显示拼接。

## 备选方案

- 在聊天中直接加载整个 `files` 组可少改加载入口，但会同时引入 PDF 和 HTML 预览等无关组件，因此分离共享高亮资源。
- 首屏直接加载 Prism 最容易保证同步颜色，但没有代码的列表和纯文本聊天也会承担下载与解析，因此按需加载。
- 新增自动语言检测库能为无标记片段着色，但会猜错终端输出，增加依赖与计算；本次只使用模型明确标注的语言。

## 影响

同一套行为覆盖 Web、iOS、Android 及不同客户端聊天；没有额外 API 查询、后台轮询或写入。共享助手增加一个小型同源脚本，Prism 仍只有一份。未知语言与超限代码没有颜色，但标签、阅读和复制均可用。原生客户端的消息样式不在本次范围。

验证覆盖 Chromium 与 WebKit 宽窄屏：Python 别名、HTML 字面内容、左右按钮顺序、300px 容器、浅深色、原文复制、跨文件预览单次资源加载、过长代码、未闭合 fence、资源失败及旧节点替换；四组共 12 项通过。源码视图 12 项、启动/Markdown 文件模式等 36 项通过。首次 Chromium 执行因未安装对应 headless shell 未启动，改用现有 Chrome；首次替换节点夹具遗漏调用方清空操作，修正夹具后仅补跑受影响检查。此处不是 iPhone 高亮或最终安装包的验收证据。

RC6 后续在三端 Test 更新后验证：LAN 与 HTTPS 显示同一 Python 代码原文、12 个颜色词元及无词元的纯文本输出；每页 Prism 仅加载一次。用户在 iPhone Test 2.1.7/build 40 确认语言标签、高亮和复制均正常。Mac 浏览器温态分词采样：71 字符 Python 十次平均约 0.09 ms、最大约 0.8 ms；55,800 字符 JavaScript 一次约 16.9 ms，仅为分词耗时，不包含布局、网络或模型生成，不能当作移动设备性能上界。
