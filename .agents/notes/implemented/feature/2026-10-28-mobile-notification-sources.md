# Agent Note: 手机按连接地址选择任务通知来源

Status: implemented

## 问题

同一手机保存正式版与 Test 的局域网、HTTPS 四个入口后，各地址独立读取收件箱，同一任务可能产生四个系统提醒。用户要求能分别打开或关闭这些连接渠道的通知。

## 决策

在手机设置增加“通知来源”，列出已保存电脑名称和完整地址，逐地址开关，默认沿用开启。规则仅存手机本地，不改网关通知配置、第三方通知或其他手机。Android 前后台收件箱提醒及可选 FCM 呈现遵守该开关；iOS 对现有前台任务提醒应用同样选择，不承诺尚未配置的 APNs 后台能力。

关闭仍保留聊天、连接和收件箱同步。切换来源使旧读取失效，重新开启的首次成功读取建立基线，不补弹关闭期间消息。移除连接清理偏好，经过既有鉴权的地址恢复迁移保留该入口选择。不同入口不按电脑名称或域名自动合并。

检索既有记录：[Android 后台通知](2026-10-27-android-background-notifications.md)、[iOS 前台通知](2026-10-28-ios-theme-and-foreground-notifications.md)部分重叠，本篇增加地址级选择，保留原认证、去重和平台限制；[投递隔离](../bug-fix/2026-10-28-notification-delivery-isolation.md)互补，无需改网关扫描与投递。主题和第三方通知记录没有被取代。

## 备选方案

网关级关闭最简单，但会同时影响所有手机和该网关的多个入口，不能满足同一手机选择地址。按名称或域名自动去重可减少操作，但正式版与 Test 可能名称相同、入口不同，不能据此推断身份或用户偏好。

## 影响与验证

四地址 HTTP 接收回归先在旧实现复现全部提醒，再验证仅选中地址提醒、静音地址游标和收件箱继续更新、服务重建恢复偏好、禁用时在途响应失效、快速开关与重新开启基线。iOS 生产同步函数以排队回调夹具验证同样的选择、代际保护及前台边界；该夹具替代通知系统类型，不作为系统实际送达证据。

Android API 35 隔离模拟器验证四个真实开关、偏好持久化、重新打开、深浅色，以及调用系统通知呈现入口时四个来源只产生一个通知。iOS 18.2 隔离模拟器验证四个地址开关、保存和重新打开、主题继承；两端截图已检查。Android 初次 UI 夹具早于对话框动画完成读取，改为等待真实控件和画面稳定后通过，没有为测试修改产品时序。

移动 Node 54 项、权限、iOS 路由与附件回归通过；Android APK、iOS 无签名包和模拟器构建通过；模块边界检查通过。iOS 新增回归加入现有 macOS CI 作业，本轮未运行远程 CI。证据与安装包保存在 `.tmp/notification-sources-20261028/`，不提交；本轮尚未在用户真机验收该开关。

## 风险

[Android 电脑选项菜单](2026-10-28-android-gateway-options-menu.md)保留手机设置入口及本篇来源偏好，不承担通知投递或修改来源选择。

开启后的首次读取用于建立基线，因此直到基线建立后才提醒新消息。手机本地选择不控制网关另行发送的 ntfy/Bark 通知。真机厂商省电策略和 iOS 后台推送仍保留原有边界。
