# Agent Note: 本地优先的 Bridge 会话置顶

Status: implemented

## 问题

置顶等待网关写入和完整列表刷新，在弱网下表现为操作没有生效。Claude 与 DeepSeek 也需要相同的 Bridge 展示偏好。

## 决策

设备先持久化最新的置顶布尔意图，立即重绘，再在后台同步。作用域使用已验证的持久网关/auth draftIdentity 加网关来源；目标键包含 provider、host 和原生会话 ID，不依赖所选模型账号或可轮换的登录令牌。退出登录暂停同步和旧响应的影响；重新验证相同身份后恢复待同步意图。最近列表优先显示置顶，项目列表保持原排序。

原 pin 请求仍接受 `{pinned}`，新增可选且必须配对的 `{clientId, revision}`。服务端在原环境数组旁保存设备与目标的最新版本，拒绝延迟的旧版本。Claude、DeepSeek 使用独立的偏好文件，接受不透明的原生 ID。偏好写入不读取原生会话详情，也不执行原生置顶。待同步覆盖层拒绝旧 GET；确认后的覆盖层保留到确认之后发起的列表读取，之后接受其他设备的新状态。

只有期望置顶布尔值进入重试队列。单次请求 15 秒后中止，临时错误以 5/15/60 秒退避；恢复联网或页面可见立即尝试。认证、权限与请求错误不自动循环。未确认时显示待同步，不宣称已经全局同步。Claude/DSH 复用原右键、长按、Shift-F10 菜单；归档入口仅接受后端已证明的可逆原生能力，仍是一次显式操作，不进入置顶重试器。

## 备选方案

保留网关确认后重绘最简单，但让本机展示偏好依赖网络延迟。仅做乐观重绘而不记录服务端版本，无法阻止超时旧请求覆盖新意图。写原生置顶违背 Bridge 内独立偏好的边界。以所选账号或 CSRF 作为偏好作用域，会在正常账号切换或重新登录时丢失置顶。

## 测试

合成夹具覆盖离线立即重绘、刷新恢复、快速反向操作、乱序写入、旧 GET、延迟认证失败、登录/网关/provider/host 隔离、旧请求兼容、原生无调用，以及 Claude/DSH 最近和项目排序、菜单能力和手势。完整前端回归 1176 通过、1 跳过；相关后端 64 通过；最后的持久化失败恢复补充检查通过（10 项本地偏好检查）。没有操作真实会话、账号或移动设备。

## 影响

弱网下置顶立即生效，设备保留尚未同步的最终选择；代价是持久设备版本元数据与一个后台偏好队列。同步完成后的新列表可反映其他设备更晚的选择。

本决定取代 [Bridge 会话管理](2026-10-26-bridge-session-management.md) 原先先等待网关写入再重绘的交互。旧笔记的原生归档、执行归属、任务与未知回执约束全部保留；安全的期望偏好同步不授权归档或消息未知写入重放。既有列表首屏、剪贴板与 WSL 身份笔记保留各自边界；检索未发现可合并的既有本地优先置顶提案。
