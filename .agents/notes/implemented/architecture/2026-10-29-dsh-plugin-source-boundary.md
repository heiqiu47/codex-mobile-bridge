# Agent Note: DSH 独立插件源码与网关内置副本的边界

Status: implemented

## 问题

用户要求独立仓库维护通用 DSH 插件。现有官方一键安装和手动导出共用 host 源码，直接移除文件会改变现有安装行为。

## 决策

独立本地仓库 `dsh-codex-mobile-bridge` 持有完整运行时、原许可、来源清单、回环协议测试与可复现包脚本。Bridge 保留当前内置副本，通过 `plugin-source.json` 固定独立仓库提交。检查脚本只读取明确指定本地仓库的固定 Git 对象，逐字节比较运行时和许可证，并比较包版本、核心版本与协议字段，不读取浮动工作区、不连接网络、不更新真实接入。

后续插件运行时修改在独立仓库完成后，同步到 Bridge 专题分支并更新固定提交。文档和仓库元信息可以各自维护；运行时变化必须一起审查。没有添加远程、发布 npm 或创建公开市场。原包作者与 `coding-mobile` MIT 许可保留，独立仓库初始导入不声称继承完整作者 Git 历史。

## 备选方案

立即删除内置副本能消除物理重复，但冻结分发和原生一键安装需要它，当前不迁移加载路径。仅复制一个独立目录更简单，但无法发现日后偏离，因此增加固定提交检查。

## 验证

独立仓库的插件回环测试与可复现打包测试通过。Bridge 检查覆盖正确固定提交、工作区变化不影响固定源、内置文件漂移和版本字段漂移。本轮不改变产品逻辑，不代表独立包已重新通过三平台真实安装。

## 影响

插件有独立维护入口，现有安装与导出不变；代价是维护者需要显式同步。未来公开仓库与市场仍需用户授权，源码拆分不隐含发布。
