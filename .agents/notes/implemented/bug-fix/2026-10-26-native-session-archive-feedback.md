# Agent Note: 原生归档的执行归属与 provider 可逆支持

Status: implemented

## 问题

空闲的 Codex App 线程仍持有原生写入锁。第二个短时 app-server 可以读取元数据，却不能归档它。Bridge 将明确的原生拒绝掩盖为未知写入。Claude Code Desktop 和 DSH 也有可逆的原生归档接口，但共享管理路由尚未接入。

## 决策

Codex 保留原执行归属边界。归档 RPC 错误响应转换为 `ArchiveRejected`，与断开、EOF 和超时区分。网关在明确拒绝前后读取完整、已授权的根及后代归档标记。只有完整元数据完全一致，才移除这次新建的待处理意图，并返回明确的 409 `archive_rejected` 错误及可采取行动的原因。部分变化、缺少证据和传输不确定性仍作为未知结果持久保留。已有未知回执若没有拒绝证据，绝不能仅因根会话仍未归档就清除或重放；现有原生标记成功核对保持只读。

已安装的跟随协议尚未证明存在由外部调用原归属进程、归档已加载本地 Codex App 线程的路径。第二运行时遭遇写入者拒绝时，引导用户前往原归属客户端，而不报告归档成功。Bridge 不恢复或接管线程，不伪造同步广播，不关闭 App，也不修改 Codex 数据库/保存记录文件。没有写入者的已保存 App 线程仍可使用原主目录/运行时。Codex CLI 和 WSL 使用现有原守护进程/原生连接；独立持有的写入者仍由原生机制拒绝。

仅当原生 Code 界面提供 getAll/getSession/archive/unarchive 时，Claude Code Desktop 才暴露 `mobileArchiveState` 和 `mobileArchive`。新读取的 App 内元数据校验精确根、附加后代、空闲状态、待处理批准/同意、保留输入、后台活动和待处理子任务。原生归档只接收 `{cleanupWorktree:false}`；恢复使用原生 unarchive。不以 force/discard/stop/resume/delete 替代。仅元数据方式加载已归档会话，使恢复候选可见而不启动轮次。Cowork 和其他 Claude 界面不继承此 Code 能力；CLI 文件级归档另有下述验证门槛。

DSH 仅在两个方法都存在时，暴露原生 `workspaceRegistry.archiveSession(sid,{})` 和 `unarchiveSession(sid)`。从不请求 stopActivity。注册表串行化的活动提供者保护在写入前拒绝活跃子任务/后台工作。Bridge 另外检查当前运行/批准证据。已验证的原生活跃会话拒绝，属于已知预检未发送；其他原生失败除非单独证明，否则保持不确定。原生归档可能作为生命周期副作用清除 DSH 自身置顶；本决定不引入原生置顶操作。

`POST /api/desktop-sessions/{claude|deepseek}/archive` 接受既有通用请求体身份 `sessionId`，以及 `{archived,id}`。provider/环境/原生 ID 映射为私有回执身份；原生回读成功后返回已确认。管理器保留启用/账号检查，并在派发前拒绝排队中/未知写入回执。共享中继只新增精确的归档 POST。列表行/详情根据实际可逆原生支持声明 `capabilities.archive` 和 `capabilities.unarchive`。

Claude 连接器修订 11 和 DSH Bridge 修订 6 要求更新后的连接器能力证据。DSH 生命周期兼容保留修订 3–5。已发布修订 5 的精确 LF/CRLF 哈希仍被识别，用于显式、经过归属检查的升级；既有凭据、源码归属和不确定请求记录保留。本次修改的测试不安装或重启连接器。

## 既有笔记审计

[Bridge 会话管理](../../implemented/feature/2026-10-26-bridge-session-management.md)仍约定仅限 Bridge 的置顶、分页及原环境保护。本笔记以存活写入者约束收窄其中的 App 归档支持表述，并新增原生 provider 支持。此前隔离归档检查关闭了源运行时，未覆盖空闲但仍加载的写入者。不会根据此前测试追溯重分类旧回执。

## 备选方案

- 通过第二 Codex 运行时重试或恢复线程：跨越原执行归属边界，且无法安全解决写入锁。
- 伪造线程已归档广播或修改原生元数据文件：没有受支持的归属进程操作，却可能改变展示/状态。
- 在 Bridge 隐藏行或用删除替代：不能实现原生归档/恢复语义。
- provider 归档期间强制停止活动：原生方法能停止任务，但当时要求的保护是拒绝活跃工作。

## 证据与测试

确切安装版本 Codex App 26.1021.31345 内置运行时 0.164.0-alpha.11.1。两个同时运行的隔离运行时复现用户可见失败：源运行时报告空闲，第二个返回 `already has an active writer`，archived 保持零。另一个未触碰的线程在源运行时关闭后可归档。通过同一源运行时归档，则在其保持打开时成功。修正后的生产辅助程序在并发场景返回精确类型的拒绝。这些夹具使用空的合成线程，不进行模型轮次，不使用真实账号或凭据。

已发布 Claude 3.1623.0 源码确认 Code 归档/恢复和工作树选项。该版本 Cowork 归档带额外停止/输出清理副作用，且未暴露对应恢复，因此不视为可逆 Code 归档。DSH 0.2.1-rc.3 已发布注册表源码确认持久归档集合、默认拒绝活跃工作、恢复保留已记录成员关系；检查不修改任何真实原生会话。

定向 Python 测试覆盖短连接/本地守护进程/WSL 通道上的明确 RPC 分类、完整子树标记、已证明无效果后的重试、部分变化/传输/旧未知结果保护、provider 归档/恢复及 HTTP 登录/CSRF/中继边界。真实连接器/宿主 JavaScript 夹具验证 Code 后代、同意/后台/输入保护、cleanupWorktree:false、DSH 默认活动拒绝和不调用 stopActivity。相关既有连接器/生命周期、适配器、迁移及资源回归通过。真实用户 App/Claude/DSH 会话、账号文件和未知回执未被触碰。

## 影响

完整元数据证明无效果时，已知原生拒绝不再表现为丢失的归档写入。可逆 provider 操作使用原原生服务，缺少证据时保留不确定性。不默认为已修复已加载 App 会话归档：已安装外部跟随协议缺少该归属进程操作。原生 API 仍无跨客户端的原子条件归档，其他客户端可能在独立读取与修改检查之间改变状态；原生默认拒绝和原执行归属边界仍不可缺少。

## Claude CLI 可逆文件归档

在调查发现普通本地 CLI 尚无经过验证的归档命令后，用户批准文件级归档。它不是仅限 Bridge 的隐藏标记，也不是原生归档 RPC。原 JSONL 从 `projects/` 移至同一配置中的 `bridge-archives/<UUID>/`，不重写字节。规范配置路径、UID、目录设备号/inode、稳定主机身份、原项目名称及哈希记录在持久清单中；将包复制到另一配置不构成恢复授权。原生 UUID、cwd、账号/来源和历史仍属于原记录。精确的平台/CLI 版本组合只有在隔离原生选择器显示会话消失及重现后，才加入 `VERIFIED_PICKER_VERSIONS`；已启用经验证的 macOS 2.1.292 原生二进制 SHA-256 `97a01e5bc74a199e67189435d0331ea3a24eac2e07db4b76d9148c5b0386138f` 和 Linux 2.1.308 原生二进制 SHA-256 `356733f185fa988e6bf3aa9a555269fdd167982a2e2a80d3c8a78037bb92ad58`。未验证原生发行版、JS 替代版本及 Windows 仍禁用，等待单独原生验收。仅有合成存储测试不能启用某个组合。

已安装 2.1.292 在正常退出时移除 PID 记录，还可能有条件地跳过注册，因此不要求存在匹配的死亡记录，空注册表本身也不充分。适配器要求既有覆盖完整配置、感知 PID 代次的保护，以及新取得的同 UID 可执行进程清查。清查拒绝已知原生 Claude CLI 身份、原生版本目录可执行路径和已知 Anthropic Node/Bun 入口脚本；检查入口脚本身份，但不记录提示词参数或环境。无关 Node/Bun 开发工具仍允许存在。Claude 进程证据不可访问或无法分类时拒绝操作。修改前立即重新核验精确二进制指纹；能力哈希期间发生程序更新，会禁用该能力而不破坏列表。这是已验证原生发行版的边界，不声称识别任意重命名/自定义脚本。存活的 Bridge 执行器、活跃/待处理工作、配置变化、未知原生版本或管理器已有不确定回执都会阻止派发。归档不停止或恢复进程。原生注册表检查不是阻止其他 CLI 在检查与修改之间启动的原子锁；剩余竞争不被描述为独占归属。

只移动主记录。原生 UUID 私有目录和 `file-history/<UUID>` 独立复制进包，原件保留原位；若原生孤儿/保留期清理以后删除原件，已知的会话专属数据仍受保护。共享任务列表和项目记忆不变。恢复校验备份哈希，只补齐缺失私有文件，拒绝内容不同的既有文件，绝不覆盖新记录。存在硬链接、符号链接、其他 Unix 用户归属或跨文件系统链接失败时，拒绝移动。副本不与原生附属文件共享 inode。

被动列表/历史状态检查文件类型、归属和位置，不计算整个记录的哈希；显式归档状态验证及修改则重新校验归档哈希。同文件系统 link/unlink 事务使用独占私有事务目录，通过随机名称、mode-0600 临时文件写入并 fsync 意图/提交记录。绝不打开或覆盖预先存在的可预测临时名称符号链接；替换失败会清理自己的临时文件。目标链接创建以原子方式拒绝既有文件。进程内 unlink 失败会回滚已核实的重复副本；中断的 preparing 记录、过期事务目录、冲突副本或哈希变化需要人工检查，绝不自动重放。恢复后的原生会话可以正常增长，下次显式归档刷新快照/哈希。恢复不选择原生会话，也不执行轮次。Linux 持久身份使用机器 ID、规范配置路径、UID 和目录设备号/inode；PID 命名空间只用于即时写入者检查，因此普通发行版重启不会使保存包失效。Linux 验收仅适用于独立测试过的精确 2.1.308 原生二进制；Windows 不继承该证据。

合成测试覆盖精确 CRLF/NUL 字节与身份、归档后的列表发现、恢复/冲突/篡改拒绝、原生附属文件删除及仅缺失恢复、共享记忆保留、原生增长后再次归档、活跃写入者拒绝、硬链接/符号链接、中断日志与 unlink 回滚。主智能体在操作系统强制断网的隔离合成配置中，完成实际 macOS 2.1.292 选择器检查：精确 516 字节的合成会话在归档前出现，移动主记录后从当前项目和全部项目列表消失，精确字节恢复后重现。取消选择器进程时未选择会话或执行轮次。证据保存在任务 `.tmp/claude-archive-research-20261026/manual-native-picker-acceptance.json`。不完整/损坏包生成可见的“Claude Code 归档待核对”占位和覆盖不完整状态，有效会话仍列出；此类包不能自动恢复。未移动真实用户历史，也不依据合成扫描夹具推断原生能力。

### Linux 原生选择器与写入者身份证据

经批准、已运行的 WSL Linux 2.1.308 二进制独立通过真实原生选择器序列：合成标题在归档前出现，随后从当前项目和 Ctrl+A 全部项目视图消失，精确字节恢复后重现。每阶段均在新的用户/网络命名空间中运行，无出口路由，IPv4 返回 ENETUNREACH。仅对子进程生效的 Landlock ABI 3 白名单在原生 exec 前证明，打开真实主目录和外部合成哨兵文件返回 EACCES。合成配置只预置经批准的空合成项目的信任，以及无效假密钥的接受状态。未选择会话、未发送模型提示词；取消选择器后，所有持有的原生子进程均退出。证据保留于任务 `.tmp/hands-on-feedback-20261026/claude-wsl-picker-payload/native-evidence/` 和 `native-linux-acceptance.json`；未移动真实历史。

以原生版本命名的进程显示为 `comm=2.1.308`，因此将 Linux `ps comm` 当成完整可执行路径会漏掉写入者。仅复制到合成原生版本形状路径中的公开 sleep 二进制复现了遗漏。Linux 现在依据已知 Claude 名称、选定二进制的 15 字符基本名、原生版本形状基本名及 Node/Bun 名称筛选候选。已知 Claude 名称直接拒绝；其他候选需读取实际 `/proc/<pid>/exe`，并在读取前后取得新的同 UID、同 PID 命名空间及稳定启动时钟证据。已知安装路径分类前移除 ` (deleted)` 后缀，因此仍在运行但已解除链接的旧原生版本仍算写入者。只跳过进程目录已消失的情况；存活进程缺少可执行元数据、权限失败、命名空间/归属变化或代次变化时均拒绝。

普通非候选进程不会仅因 `/proc` 元数据受保护就成为新增归档前提。这避免了无关的不可转储系统服务阻塞全部操作，也不引入服务名称例外。边界仍是已知原生发行版和已知 Node/Bun 入口脚本，不是任意重命名/自定义程序。最终完整清查允许空闲状态，以明确 CLI 写入者原因拒绝存活的合成原生版本进程，也拒绝其可执行文件已删除状态，在其自然退出后再次允许。单元回归覆盖非候选不可读、候选信息未知、选定/其他版本、已删除可执行文件身份、PID 复用及 UID/命名空间变化，不读取原生候选参数或环境。

元数据选择依据 Linux [proc_pid_comm(5)](https://man7.org/linux/man-pages/man5/proc_pid_comm.5.html)：comm 可修改，且包括 NUL 在内限制为 16 字节。[proc_pid_exe(5)](https://man7.org/linux/man-pages/man5/proc_pid_exe.5.html)说明实际可执行路径、删除后缀、ptrace 访问检查和主线程元数据缺失情况。即时进程清查和注册表读取仍无法原子阻止另一 CLI 在验证后启动；不声称存在跨客户端生命周期锁。

## 归档前确认停止的后续决定

[确认断开连接并归档](../feature/2026-10-27-confirmed-disconnect-archive.md)对显式 `disconnect:true` 请求部分替代仅空闲规则。旧请求和恢复仍只允许空闲状态；原执行归属、版本、写入者及不确定回执限制继续有效。该后续决定未移除已加载 Codex App 和未经验证 provider/平台的限制。
