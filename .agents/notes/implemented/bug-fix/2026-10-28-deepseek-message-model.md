# Agent Note: DSH 回复展示实际模型与历史请求思考强度

Status: implemented

## 问题

DSH 聊天已有模型选择器，但转换历史消息时丢弃回复的模型来源和请求的思考强度。用会话当前选择补齐所有消息会错误标注切换模型之前的回复。原生历史页是连续事件片段，请求头可能位于当前页之前。

## 决策

回复模型读取原生 `assistant/message.data.message.source`。思考强度读取该回复之前最近的 `request/header.data.header.config.reasoningEffort`，且只有请求 provider/model 与回复来源一致时才附加，缺失时不猜测。待使用的 `model/selection` 不代表已生成回复的实际参数。

DSH 插件在历史页内部顺序关联请求头；当首条相关事件已经是回复时，通过已安装 Harness 的 `sessionQuery.observeSession` 冷读当前页边界之前的最近请求头，并在 finally 中释放 observation。该读取不创建或激活 Agent，不调用 prompt/cancel/selectModel。向网关返回的补充字段只允许 provider/model/reasoningEffort 三个字符串，完整 header、系统提示和其他配置不返回。

连接器修订升为 8，旧修订的生命周期检查继续兼容，以便按现有空闲核验升级。旧接入仍可展示消息来源中的模型；没有可靠请求记录时不展示推测的强度。网页复用现有回复署名，不改变聊天布局。

### 既有记录核对

[通知投递隔离](2026-10-28-notification-delivery-isolation.md)部分重叠：两者读取 DSH 历史，但本篇仅增加显示元数据，完成状态仍要求原生 turn/end。活跃笔记中未发现已有同一模型标注决定，不改写其他接入和分页记录。

## 备选方案

直接复制会话当前 model/effort 最简单，也不用额外读取；但会把后来选择的模型标到旧回复，因此放弃。

向前反复拉取历史页只使用现有分页 API，但请求头可能距离当前页很远，重复分页会放大读取开销。使用原生查询服务冷读一次并释放；旧服务不存在时保留模型来源，不伪造强度。

## 影响

历史回复能展示自己的模型和可确认的思考强度，代价是缺少页内基线时增加一次原生冷读，以及需要更新已运行的 DSH 接入。分页、分支标识、通知轮次和账号归属不变。

回归覆盖页前请求、后续设置隔离、同页模型切换、无强度、来源不匹配、旧接入降级、原生 observation 释放及请求头敏感字段不外传。实机来源结构已只读核验，不输出聊天正文。

2026-10-28：经用户明确允许共享接入升级并接受旧正式版兼容影响，在核验全部会话空闲后，使用 Test 原生恢复流程将连接器升为 8。真实接入只读验收覆盖 4 个会话、5 个历史页：当前页 25 条与较早页 9 条回复均带有模型和思考强度。连接凭据、安装记录和 Harness 配置哈希保持一致，Test 显示接入就绪；未发送测试消息或激活新任务。旧连接器保存在本机临时目录中，验收数据不提交。
