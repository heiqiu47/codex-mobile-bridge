# Agent Note: 紧接正文的块公式解析

Status: implemented

## 问题

[Issue #94](https://github.com/try2love/codex-mobile-bridge/issues/94) 的 `\[...\]` 块公式在紧接正文、没有空行时成为普通段落，反斜杠先被 Markdown 转义处理。以本地 `b9d7b13` 为基线运行 [PR #96](https://github.com/try2love/codex-mobile-bridge/pull/96) 的原始回归，括号与双美元符号两项均未生成 `math_block`；代码及未闭合表达式检查通过。

## 决策

保留 littltstream 的原始提交 `35b9bae109d378e9f3e9e0ecf0c309825f0b0cc1`，以合并提交纳入本地历史。产品改动仅在现有 texmath 块规则注册时添加 `alt: ['paragraph']`，让完整匹配的块公式能够中断段落。沿用原规则的静默检测、分隔符、编号和 token 生成，不预处理或改写消息原文；生产渲染器继续使用原有 DOM 构造、KaTeX 安全参数和按需加载。

补充代码围栏、缩进代码、行内代码、转义符、货币、行内与独立公式、编号、列表及引用回归。已有 Markdown 和公式浏览器脚本接入 `critical.spec.cjs`，加载生产资源并核对真实断言结果，避免仅加载文件却未执行检查。

## 既有笔记审计

[Markdown 阅读与源码模式](../feature/2026-10-26-markdown-file-modes.md)与本篇部分重叠，共用渲染器；模式切换、源码复制、滚动与 Mermaid 生命周期不变。源码查看器笔记和启动资源恢复笔记与此次段落规则决定无关，保留原状，没有被取代的历史决策。

## 备选方案

- 在输入渲染前补空行：能直接避开段落连续解析，但需要额外识别代码与转义边界，还会改变解析所用的原文及行位置；采用解析器原生的段落中断机制。
- 要求用户或模型始终输出空行：无需改动解析器，但既有聊天和流式输出仍可能触发故障，不能满足直接展示既有内容的需求。

## 影响与验证

正确分隔的块公式不再依赖前置空行。聊天与 Markdown 文件阅读共用这一解析入口；未新增样式、设置、依赖或平台分支。维护代价是在本地 vendor 补丁之外保留相关回归，后续更新 texmath 时仍需验证该段落行为。

Mac 本地验证：11 项 texmath 用例通过；完整 Node 前端测试 1,251 项通过，1 项 Windows WinError 32 专属用例按既有条件跳过，无失败。实际 Chromium（本机已有 Chrome）与 WebKit、1280 px/390 px 四组均通过，每组执行 15 项 Markdown 和 13 项公式断言，包括链接安全、无空行公式原文、未闭合流式内容、代码和横向滚动。8 项 Web 资源用例、模块边界检查与差异空白检查通过。日志与浏览器报告位于 `.tmp/pr96-20261028/`，不提交。
