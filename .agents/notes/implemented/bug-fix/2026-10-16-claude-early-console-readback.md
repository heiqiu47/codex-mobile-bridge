# Agent Note: macOS 上更早回读 Claude 控制台

Status: implemented

下述前台采集策略由[直接提交](2026-10-16-claude-direct-console-submit.md)替代。历史测量与被否备选仍有参考价值。

## 问题

macOS 辅助程序向 Claude DevTools 控制台输入约 25 KiB 连接器源码，并在 Enter 前要求一次完整辅助功能回读。较长 CodeMirror 行可能只暴露虚拟化片段。辅助程序先等待四十次、每次 25 ms 的读取，再尝试有界光标导航。真实 Test 工作区探测中，第 4 次和第 40 次都只暴露相同的 10,077 个单位，总长为 25,020 个 UTF-16 单位，因此该次等待未显示更多文本。

## 决策

源码长于 3,500 UTF-16 单位时，四次相同、非空且精确为预期源码子串的 AXValue 读取，允许提前使用一次现有光标显露步骤。只有完整精确回读才成功。提前步骤未验证源码时，继续原四十次读取周期，并保留原三次光标显露尝试。提前移动光标后若后续读取成功，提交前将光标移到末尾。每次按键前执行焦点、选定应用及控制台检查。源码格式、归属交接和已签名连接回执不变。

## 备选方案

短加载器若读取完整网关持有脚本、验证固定 SHA-256 再动态求值，可避免输入长源码。但已安装 Mac Claude Desktop 上两个无害 nonce 探测都返回 `EvalError`：一个在异步文件读取后求值，另一个暂存已验证 nonce，另行同步控制台提交。真实长源码探测的选中文本检查返回零字符且干扰回退，因此移除。另一 Windows UI Automation 探测只选到 24,954 个单位中的 7,577 个，该快速路径也移除。把完整编辑器复制到系统剪贴板需保留全部既有剪贴板格式，超出本次狭窄修改范围。

## 影响

提前步骤取得完整回读时可省去固定等待；仍在稳定的编辑器继续获得原完整等待和回退，最多增加一次光标尝试。实际 25,020 字符 Mac Test 探测使用提前辅助程序，于 2.429 秒取得完整执行回执。更早的旧辅助程序在不同条件下耗时 2.108 秒。后来一次使用相同 25,020 字符源码的成对热 Test 中，旧程序 2.094 秒，新程序 0.931 秒，两者均取得完整源码回执。一对测量不能证明所有机器或完整连接均提速。Swift 夹具覆盖提前成功、后续稳定读取、原导航及失败路径。
