# Agent Note: Claude 与 DSH 发送期间的即时反馈

Status: implemented

## 问题

Claude Code、Cowork、CLI 和 DSH 共用的 `DesktopSessionsView.submit()` 等待网络写入期间只禁用按钮，没有显示正在提交的内容，成功回执后也没有临时提示。慢连接因此看起来像点击无效。先写的合成回归确认旧实现没有发送反馈节点；现有 Codex 发送成功与排队提示是统一用词的依据。

## 决策

在通过输入、附件和待确认记录检查后，立即在输入区显示紧凑的原文预览及“正在发送…”，同时改变发送按钮文字。预览属于当前发送操作，不放进原生历史，不伪造消息 ID、原生送达状态或重复消息气泡。原生历史在回执之前已经出现相同内容时，也只有一条历史消息。

预览按网关、provider、会话和草稿账号限定。切换上下文时清空隐藏节点内的正文，退出登录清除临时操作引用。回执或异常结束后移除预览；成功时只在原上下文提示“已发送到会话”，排队则提示“已加入待发送队列”。迟到的发送错误也不显示到其他 provider。此提示证明原客户端接受请求，不表示模型任务已完成。

原有草稿版本、附件、引用、请求 ID 和未确认台账继续决定确认与清理；不为改善反馈提前清空草稿，也不自动重试未知结果。发送期间编辑的新草稿保持。错误时原内容仍在输入区及既有未确认记录中恢复。该共享页面覆盖 Claude Desktop Code/Cowork、Claude CLI/WSL 和 DSH 网关聊天；DSH Mobile 直连显示第三方原生页面，本次不注入替代发送逻辑。

## 既有记录核对

检索活跃记录中的发送、草稿、未确认、unknown：

- [Claude Code 会话恢复](../feature/2026-10-14-claude-code-sessions.md)部分重叠：保留原生身份、只在显式操作后激活及未知结果不重放，本篇仅补前端状态反馈。
- [DSH 消息模型](2026-10-28-deepseek-message-model.md)记录历史归属，与本次展示交集仅在原生历史不被虚构；其模型来源决定不变。
- 其余命中涉及通知投递、控制台初始化、账号隔离、会话菜单、归档及启动恢复，与本次发送等待显示无关。没有被完全吸收或过时的发送预览提案。

## 备选方案

将提交内容立即插入原生时间线，最接近已经送达的消息气泡；但原生消息尚无可靠 ID，跨端历史先到、排队与未知结果会带来错误去重和送达暗示。独立的临时预览能即时反馈而不改变历史语义。

只改按钮为忙碌文字不增加内容区，改动最少；但用户仍看不到正在提交哪条内容，因此同时展示有高度上限的原文预览。

## 影响

Web 与手机共享页面获得相同的即时反馈，使用既有主题变量与队列卡样式，不增加 API、存储格式、网络请求或宿主注入。新增少量临时 UI 状态与有界文本展示；真正耗时仍取决于信道和原生客户端，反馈并不宣称降低端到端延迟。

## 验证

Node 夹具执行生产页面逻辑，覆盖延迟回执期间的同步预览、重复点击拦截、原生历史先到、不覆盖后续草稿、接受与排队提示、未知回执和断网保留请求 ID、上下文切换与迟到错误隔离。浏览器专用用例使用生产资源和合成 Claude Code/Cowork、DSH 会话，在真实聊天页面核对预览可见、按钮禁用、草稿保留及未知结果无成功提示，并保存浅色/深色截图；不访问真实账号或调用模型。构建及设备验收由本轮集成统一完成，不把合成用例表述为真实客户端发送实测。

本轮 Node 页面回归 158 项通过，浏览器 12 组通过（已安装 Google Chrome / WebKit，各自宽屏与窄屏）；抽查窄屏深色 Claude 与宽屏浅色 DSH 截图，预览位于真实聊天输入区且无横向溢出。浏览器首次失败分别来自夹具选择器同时命中主页面与合成页面、页面模块尚未就绪及本机缺少 Playwright 专用 Chromium；修正夹具限定与就绪等待，并采用已有 Chrome 后通过，未因此改变产品逻辑。
