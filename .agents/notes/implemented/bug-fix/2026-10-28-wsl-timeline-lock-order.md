# Agent Note: WSL 时间线读取的锁顺序

Status: implemented

## 问题

Windows Test 实测中，Codex WSL 列表约 0.7 秒返回，但同一会话详情连续两次超过 40 秒。独立只读探针连接原生服务约 0.6 秒，线程状态约 0.02 秒返回；同源码的隔离 WslEntry 首次视图约 0.34 秒返回，随后已连接。现场 PID 41632 的 py-spy 线程栈进一步确认：`timeline_read → view → _queue` 等待写入门，`activate` 已持有写入门并等待会话条件锁，后台刷新和事件线程也被阻塞。采集仅包含调用栈，没有局部变量或内存转储。

代码中存在可确定复现的锁顺序冲突：`timeline_read()` 持有 `session.condition` 时调用 `view()`；后者通过队列和提交回执读取获取 `write_lock`。写入路径先持有 `write_lock`，再更新会话状态，因此并发时可以相互等待。旧版本也存在这段锁顺序，不能仅因新版实测触发就断言它由本轮新增功能引入。

## 决策

时间线先在会话条件锁之外取得只读视图，再持有条件锁更新投影和读取分页。这样不会在持有会话状态锁时等待写入门。较早取得、较晚到达的快照不得覆盖已发布的新序列投影；更新仅接受不小于当前时间线序列的快照。

写入互斥、停用等待、操作回执和原生归属核验保持原样。读视图仍不恢复未加载会话、不启动模型任务。此项修正针对已复现的锁顺序缺陷；Windows 换包后的原会话验证见测试记录，不能据此声称所有历史会话都能恢复。

## 既有决定

[WSL 统一接入](../architecture/2026-10-24-codex-wsl-unified.md)的停用与写入串行化继续成立；本次消除读取路径与该写入门的反向获取顺序，不移除写入保护。[三平台测试记录](../testing/2026-10-28-regression-and-dependency-gates.md)中的安装成功不替代真实聊天打开路径验收。

## 备选方案

- 延长 HTTP 超时或反复重连不能解除相互等待，且会增加悬挂请求。
- 去掉队列读取的写入锁可以绕过这次等待，却会破坏回执读取与写入、停用之间的已有契约。
- 将整个时间线过程放入写入门可以统一部分锁顺序，但会把视图组装及其他读取纳入写入临界区；这里采用较小的快照边界调整，并校验序列不倒退。

## 影响

时间线等待回执时不再阻止写入者取得会话状态锁。快照读取与投影更新不再处于同一个临界区，因此需要拒绝迟到的旧快照。界面资源、账号配置、原生权限和持久化格式不变。

Claude WSL 必须独立判断：本轮一个可恢复的实际样本在 6.7 秒内完成原生初始化，未发送模型消息；另一个历史样本无法确认原权限模式，被既有前置检查拒绝。不能把这两者都归因于 Codex 的时间线锁，也不能通过猜测权限解除保护。

## 测试

新增用例让写入者先持有写入门，等待真实 `timeline_read()` 读取回执，再尝试取得会话状态锁。旧实现稳定失败；修正后通过，且有界释放和清理不遗留死锁线程。另一个用例模拟新投影已发布后旧快照才返回，确认序列和标题不会倒退。

本地 Python 3.12 下，相关 WSL、时间线、终端、账号边界与生命周期等 198 项通过；没有以这些测试代替 Windows 冻结包验收。2026-10-29，Windows 安装 `026784022ab5` 对应的 Test 后，原先卡住的会话首次详情在 0.531 秒返回渐进加载状态；显式重连与时间线、详情并发执行，约 2.03 秒完成。随后详情显示已连接、历史加载完成和 5 轮历史，时间线包含 9 行；详情与时间线分别约 0.000 秒和 0.016 秒返回。该复测不发送模型消息。诊断只记录阶段耗时、状态、错误和计数，不记录聊天正文或账号凭据。

Windows 旧网关无法正常退出，经用户明确允许后，仅按 PID、启动时间和可执行文件身份结束该卡死网关；其托管 CLI 随后退出。15 个原生应用进程及原 WSL Codex daemon 保持同一身份，历史未知结果回执未清除、未重放。新 Test 的 735 个安装文件逐个核验，配置、账号、浏览器数据及正式版保留。Claude 桌面恢复既有连接后，同一个已知权限的 WSL 样本在 7.5 秒内恢复至 `ready`，后续详情为 `idle` 且 `runtimeKnown=true`。此前权限无法确认的历史样本仍按既有规则拒绝恢复，没有猜测权限。

Mac、Windows、Linux 均完成原生构建、冻结包回归、覆盖安装和服务启动。Windows 原桌面会话确认 Test 窗口存在且响应；Mac 已检查实际界面；Linux 确认原 Wayland 会话中的 GUI、渲染进程及健康检查，未作远程窗口截图验收。临时构建与实测记录保存在 `.tmp/v217-wsl-cards-20261028/`，不提交运行数据。
