# Agent Note: 在 Claude 前台控制台直接提交

Status: implemented

## 问题

前台初始化会在 Enter 前明显导航长控制台草稿，以采集辅助功能文本。源码已在本地生成，但 Chromium 通过 AX/UIA 可能只暴露视口片段。因此完整回读让正常连接路径重复移动光标，并将有限辅助功能可见性误判为输入不完整。

## 决策

显式前台初始化器写入准备好的源码一次、派发 Enter 一次，不执行 Home、Down、End 或选择导航。保留选定应用身份、窗口、提示区焦点、取消和现有草稿保护。有界、无导航读取检查编辑器已显示本次输入：macOS 接受精确值或至少 32 UTF-16 单位的稳定匹配片段；Windows 立即接受精确文档，或在短稳定期后接受兼容且唯一定位的片段/虚拟化间隙。这些检查证明观察到输入，不证明完整源码。macOS 保留一秒延迟读取容忍；Windows 最多等待 1.2 秒，局部视图稳定期为 250 ms。

Enter 按下/抬起之后，前台辅助程序报告已提交，由现有归属进程等待当前代次的已签名回执。Mac 不把立即焦点变化或无法访问的空提示区解释为派发失败。Windows 移除固定 700 ms 提交后等待。缺少回执不变成已连接，也不自动再次提交。信任、归属交接、活跃工作和请求重放规则不变。无人值守 Windows 后台路径保留严格完整文档检查。

Mac Unicode 输入回退保留每个事件的焦点检查，在全部分块后仅执行一次相同就绪检查，不再每 128 个单位要求完整 AX 回读。

## 备选方案

此前 [Mac 提前回读](2026-10-16-claude-early-console-readback.md)和 [Windows 自适应采集器](2026-10-16-claude-adaptive-console-readback-windows.md)保留提交前完整文本相等性，却仍明显导航控制台。本决定替代它们的前台采集策略。被否的选中文本和动态加载器实验仍有价值：选中文本 API 也返回局部值，使用 eval 的加载器被 Claude CSP 拒绝。不引入剪贴板访问、CSP 变更、新权限或动态加载器。

仅将 SetValue 成功视为连接成功被否决：平台赋值不能证明脚本执行。以既有已签名连接握手为最终依据。仅缩短导航等待仍保留用户报告的退化。

## 影响

正常前台提交不再滚动整个草稿。局部可见读取不能证明每个字节均在，因此仍须既有 Bridge 协议确认执行成功。输入视图不可读或无关时，止于 Enter 前；没有心跳时，止于连接成功前。原生测试覆盖片段/空白/变化视图、错误内容、派发前取消及焦点变化、单次 Enter 和禁止重放。真实 Test 证据及安装包结果记录于 `.tmp/claude-direct-submit-20261016/acceptance.md`；凭据或真实聊天正文不提交。
