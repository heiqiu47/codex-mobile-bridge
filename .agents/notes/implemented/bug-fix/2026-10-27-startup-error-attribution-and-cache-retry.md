# Agent Note: 启动错误归属与失败资源缓存重试

Status: implemented

## 问题

[Issue #87](https://github.com/try2love/codex-mobile-bridge/issues/87) 报告 iOS Safari 访问 HTTPS 入口时启动失败。既有 bootstrap 把任何窗口运行时错误或未处理 Promise 拒绝都视为启动依赖失败；不属于必需脚本、甚至没有来源的错误也会中止队列。资源失败后重复插入相同 URL，还可能持续复用失败结果。

在本地基线 `a5fc906`，使用生产资源与合成故障的 24 项 Chrome/WebKit 宽窄视口检查中，18 项失败、6 项通过。无来源错误、非必需脚本异常或拒绝、失败的脚本响应均可阻断登录；WebKit 的连续脚本资源失败也不能恢复。这些复现证明代码路径存在问题，不能据此断定报告者最初的错误来自某个扩展或特定缓存。

## 决策

纳入 [PR #88](https://github.com/try2love/codex-mobile-bridge/pull/88) 的原始提交 `40a53caa5928836e9a430b1cdba4adc245dcbc54`，保留作者 waken（GitHub：mc373906408）的提交身份。生产改动仅在 `web/shared/bootstrap.js`；本地合并保留既有浏览器测试服务入口，并补充回归与文档。

即时致命错误必须归属到同源必需启动脚本。来源优先使用事件文件名或错误对象的来源字段；必要时检查有长度和帧数上限的堆栈，采用首个可识别来源帧，不因后续出现应用调用者就将注入或可选脚本认作必需依赖。bootstrap 自身、提前加载的剪贴板脚本及非按需启动脚本属于必需集合。无法归属时仅保留经过净化的错误类型与事件种类，不取消启动，也不刷新启动时限；必需脚本的可归属错误仍停止后续依赖。

首次资源请求和预加载保留原内容版本 URL。加载器确认资源失败后，或进入原有首批资源失败补偿路径时，后续尝试使用同源、同路径、保留版本参数的 `bridge_retry` 查询键。包括首次请求在内仍最多三次。正在挂起的脚本不能因超时被再次插入；语法或运行时错误不变成资源重试。样式顺序、原生剪贴板提前加载、认证只读重试和配对等写入不重放均保留。服务端对额外查询参数沿用 `no-cache`，不改变资源字节、ETag 或 CSP。

常规浏览器回归取消 WebKit 的 `known-baseline` 豁免，要求连续失败恢复真正通过，并加入无来源错误、非必需脚本异常、非必需 Promise 拒绝及错误脚本响应四类场景。

## 既有记录审计

[启动资源恢复](2026-10-22-startup-resource-recovery.md)部分被替代：保留其并发、执行顺序、时限、配对和剪贴板边界，只替代失败重试复用原 URL 及不区分来源的致命错误判断，旧理由留在原文并互链。[浏览器回归门禁](../testing/2026-10-28-regression-and-dependency-gates.md)的预期失败处理在修复后退出；原验收数字保留，不改写为当时已经修复。其他客户端启动和账号缓存笔记属于不同机制。

## 备选方案

- 继续把所有全局错误立即视为失败：实现简单，也能尽早暴露无法归属的真实异常；但复现表明无关错误会阻断本可完成的启动。因此仅将有必需来源证据的错误作为即时失败，其余保留诊断和既有超时边界。
- 失败后继续复用同一内容版本 URL：可最大限度复用缓存；但重复插入不能排除失败结果复用。仅在确认失败后的有限尝试增加缓存键，保留正常首次加载的缓存收益和执行顺序。

## 影响

已复现的错误路径可恢复登录；正常登录页在 Chrome/WebKit 宽窄视口的四组截图与修复前逐字节一致。主界面布局、颜色、账号、聊天操作及原生源码不变；失败详情新增资源尝试次数和未归属错误类型，仍默认折叠且不暴露异常正文、完整 URL 或堆栈。

错误堆栈是浏览器相关的非标准来源回退，不能保证所有异常都能立即归属。未知来源不等于无害：若启动无法就绪仍受原时限约束，后续出现新的必需错误格式需要补充对应引擎的复现。额外缓存键仅用于失败重试，会产生新的网络请求；不承诺清除生产代理或浏览器的任意缓存。
