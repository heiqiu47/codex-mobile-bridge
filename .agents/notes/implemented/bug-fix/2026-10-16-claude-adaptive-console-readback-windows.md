# Agent Note: Windows 上更早完成 Claude 控制台回读

Status: implemented

下述前台采集策略由[直接提交](2026-10-16-claude-direct-console-submit.md)替代。历史测量与被否备选仍有参考价值。

## 问题

Windows 辅助程序按 Enter 前通过 UI Automation 校验约 25 KiB 的多行 Claude 控制台脚本。采集器在每次视口移动及焦点检查后固定等待 200 ms，尽管渲染器在导航键发出时就开始稳定。无害的 Test 工作区诊断中，七个导航步骤各自于 50、100、150、200 ms 读取的源码片段均相同。该次运行提示区检查耗时 24–43 ms，文本读取 2–9 ms。

## 决策

每个导航键调用返回后立即启动稳定计时。精确完整源码回读在 50 ms 后即可成功。局部视图始终等到该键发出至少 200 ms 后，才计入源码覆盖或导致拒绝。每个导航键之前的焦点检查保留；移除相邻按键回调内的重复检查。导航后及每次读取前仍执行焦点和超时检查。18 步上限、六秒截止、覆盖规则及单次提交规则不变。

## 备选方案

Test 构建曾尝试在 50 ms 取得唯一连续局部片段后前往下一视口，但独立审查发现渲染器可能在 50 ms 暴露短有效前缀、200 ms 暴露较长前缀，提前导航会跳过源码。该路径在发布前移除。真实 Test 探测的选中文本仅暴露 24,954 个 UTF-16 单位中的 7,577 个，因此该快速路径也被否决。无害 Mac 控制台探测在 App CSP 下遇到 `EvalError`，因此动态短加载器被否决。

## 影响

早期精确读取可提前完成完整源码证明。所有局部读取仍保留从导航计时的原最小 200 ms 稳定期，焦点检查可与其重叠。原生自检除既有完整覆盖及禁止提交情况外，还覆盖早期 32 字符前缀到完整稳定时增长为 1,500 字符、后续连续视口及早期完整精确回读。最终采集器编译并通过原生自检，对 24,954 字符 Windows Test 源码于 4.407 秒取得完整源码回执。单次运行不是受控提速测量。最终 Test 包重新编译增长前缀夹具并通过包内原生自检。安装后，Claude 已运行时显式初始化约 8.1 秒连接成功，并返回真实会话列表。
