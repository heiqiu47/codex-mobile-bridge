# Agent Note: Claude 已签名连接的就绪时机

Status: implemented

## 问题

显式 Claude Desktop 初始化中，已签名渲染回执可能让 `status()` 报告已连接，但原生 DevTools 清理仍持有 `reconnecting`。这期间已认证列表请求会报“Claude 正在重新连接”。

## 决策

当前连接器的已签名回执被接受后，如果此前读取探测失败，还需既有探测成功，然后在关闭 DevTools 前将邮箱标记为可供普通调用。原生清理继续运行，在结果已知前报告 `consoleCleanupPending`。清理失败保留现有手动关闭提示。代次、归属、取消、完整源码注入和未确认写入检查继续有效。

首次显式 Windows 前台初始化中，若无已有归属进程、无持久连接令牌，则跳过控制台前等待旧渲染器跟随新代次的步骤。本次初始化注入源码前，没有渲染器能为新令牌签名。已有持久令牌、已有归属、重新连接和重启均保留交接等待。

## 备选方案

原记录对照了旧的“原生清理结束前仍阻止普通调用”与“签名回执和必要读取探测通过后先开放调用”。旧路径让清理与可用性共用等待状态，却造成已经报告连接后的列表请求被拒。首次 Windows 初始化的记录还指出，新令牌在注入前不可能由旧渲染器签名，因此只移除不存在先前归属和持久令牌时的等待。没有记录其他连接协议的比较，不补写额外选型。

## 影响

原生清理未结束时，首次列表请求已可使用建立的文件 Bridge。源码夹具在模拟 Windows/macOS 路径暂停清理，验证期间已签名列表响应。独立 Windows 夹具验证首次归属等待仅在没有持久令牌时跳过。这些夹具不测量真实启动时间，也不替代平台验收及安装包验证。
