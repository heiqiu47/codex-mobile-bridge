# Agent Note: 原生模型目录身份与手动设置兜底

Status: implemented

## 问题

Claude Code/Cowork 模型弹窗在目录为空、原生目录不允许选取或缓存写入失败时缺少 `cache.identity`，前端把缺少元数据误认成账号已切换。更新时间节点把 CSS 类名 `muted` 当成正文。目录列表同时被当作设置能力的唯一证据，使已连接且存在原生模型设置接口的会话无法手动修改模型或思考强度。

## 决策

模型目录响应始终携带读取前后核验的不透明身份，是否成功持久化与身份是否一致分别表达。前端继续拒绝真实身份不一致的目录，不能通过删除账号检查来修复空列表。手动设置携带打开弹窗时的 `modelCatalogIdentity`，网关在既有写入保护内、分发任何原生请求前重新核验；目录仍在等待时的快速手填也不能越过账号切换保护。

Claude Desktop 的会话目录合并当前已生效 API 账号的模型结果，复用账号管理已有的身份缓存和刷新路径；原生同 ID 元数据优先，以保留原生思考强度。官方账号不混入 API 账号模型，CLI/WSL/SSH 不借用本机 Desktop 账号。获取失败保留原生列表，手动输入不等待上游读取完成，迟到结果保留用户已编辑的字段。

`manualModels` 与 `manualEffort` 独立报告原生设置能力。已核验的实时能力优先于旧缓存中缺失或过期的手动能力字段。列表与手动入口共享一个弹窗，不把手填值伪装成“上游提供”。Claude Desktop 使用 `setModel`/`setEffort`，随后 `getSession` 核对实际值；CLI 使用已有控制请求与 `get_settings` 核对。手动模型请求跳过可选的 Desktop 模型目录读取，但不跳过会话归属、原生接口能力或结果核验。未知写入继续由已有回执标记待核对，不自动重放。

DSH 账号页与会话页都读取同一原生 `sessionController.modelCatalog()`，账号页仅按已配置凭据引用筛选公开来源，不维护另一份模型清单。显式手填模型跳过 Bridge 可选目录预读，但原生选择接口仍验证可用性。

DSH 增加能力字段而不增加协议动作或改变线协议版本。旧插件不会因磁盘包已更新就显示手动入口，弹窗提示升级运行中的接入插件。手填 `provider/model` 与思考强度仍经 `sessionController.selectModel`，原生 `selected` 必须与请求匹配。官方原生接口要求模型属于该 provider 的可用目录；不通过直接修改会话事件或账号配置绕过该约束。目录过期可以通过手填尝试，但原生明确不支持的模型或强度仍返回错误。

## 备选方案

仅放宽前端身份判断能消除错误提示，但会丢失真实账号切换保护。强制内置通用模型与思考强度列表能填满弹窗，却会把不存在的能力展示为可用。对 DSH 直接写模型选择事件能绕过原生目录限制，但会改变第三方客户端自身的选择规则；本次保留官方验证，并把失败明确呈现给用户。

## 验证

回归先复现空目录与缓存写入失败两条路径缺少身份。新增用例覆盖稳定身份、真实身份变化、当前 API 账号模型复用、空列表手填模型与强度、原生拒绝或不确认的结果，以及刷新期间编辑和迟到结果。源码 UI 153 项通过，覆盖 Claude 与 DSH；Python 原生/缓存/CLI/SSH/WSL 156 项、Claude 连接器 14 项及 Harness 回环协议测试通过。模块边界检查与 87 篇笔记树/格式校验通过。原生适配使用隔离回环与合成控制请求，不接触真实聊天或产生模型费用。浏览器夹具在生产资源中检查窄宽视口、慢目录与一次设置提交，供集成阶段运行。真实客户端设置操作及四种浏览器项目的执行结果由集成验收另行记录，不能以模拟测试替代。

原生 DSH 语义依据：[session-controller](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/api/session-controller/README.md)。它要求准确的 provider/model 可用目录成员；此处没有承诺任意未知模型均可应用。

## 影响

空列表不再错误阻断支持原生设置的会话，账号配置已有的模型可以用于 Claude Desktop 会话选择。目录发现失败仍可能显示错误说明；手填不会保证上游实际接受模型。模型与强度由两个原生 Claude 请求设置，第二步未确认时整体仍为待核对，不能宣称原子回滚。DSH 新能力必须更新运行中的插件才能出现；旧版本其他动作保持兼容。
