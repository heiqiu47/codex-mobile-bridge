# Agent Note: 原生项目引用与 iOS 选择器取消恢复

Status: implemented

## 问题

用户在 DSH 和 Claude 原生窗口看到 Codex 的 Files mentioned 提示包装，说明文件虽能被模型读取，却没有使用对应客户端的引用语法。iOS 相机选择取消后，其他上传入口也可能失去响应；菜单默认焦点使相册按钮持续显示黑框。用户要求移除相机入口，保留相册、手机文件和宿主项目引用。

## 决策

本篇替代[原附件记录](2026-10-29-native-project-attachments.md)中 Claude/DSH 共用 Codex 包装及 iOS 相机入口的决定，其目录权限和 Codex 附件身份仍保留。共享 manager 验证当前项目引用，向客户端适配层传递内部 `resolvedReferences`；HTTP 拒绝客户端直接提交该字段。`clients/file_mentions.py` 统一路径校验与原生 `@` 引用序列化，不读取、上传或复制文件内容。DSH 和 Claude Code 使用带空白路径的引号格式；Cowork 原生挂载映射匹配字面 `@宿主路径`，因此保留其无引号格式。上传文件仍走既有上传协议，宿主引用不伪装为上传 receipt。

历史回读仅识别用户消息末尾独立的绝对路径引用段，保留普通正文和助手内容。项目边界仍由 Workspace 二次验证，内部协议只接受绝对路径，控制字符和双引号在派发前拒绝。DSH 连接插件与协议版本不改变。

iOS 删除相机上传分支和相关代理，保留二维码扫描权限。照片取消在原生视图关闭后完成 WebKit 回调，照片和文件选择器的手势关闭也完成同一个空结果回调；票据、连接代次和同源检查继续隔离迟到结果。菜单焦点落在对话框容器，去掉容器轮廓，仍保留键盘操作按钮时的焦点提示。

## 备选方案

继续使用 Codex 包装能让模型定位文件，但客户端会展示不属于自己的提示格式，用户已明确拒绝。将宿主文件转换为上传可显示上传附件，却增加副本和字节传输，并破坏引用身份，因此不采用。直接构造 DSH `type:file` 看似更结构化，但该类型实际对应上传收据，不能填写宿主路径冒充。

保留相机并扩展权限处理能够保留拍摄能力，但用户明确要求删除，而且系统相册及文件入口已覆盖本次范围。全局移除按钮 outline 可以去掉黑框，却损害键盘操作，因此只改变初始焦点位置。

## 验证依据

当前安装客户端的只读源码确认 DSH 的 `@` 引用语法、Claude 上传参数与 Cowork 宿主挂载映射；Claude 官方文档确认使用 `@` 引用文件和目录。协议与历史测试覆盖中文、空格、Windows 路径、目录、无内容读取、幂等请求以及 HTTP 拒绝伪造内部字段。68 项引用专项、完整前端 1312 通过/1 跳过、源码后端 2835 通过/38 跳过；后续审查新增测试单独记录。Chrome/WebKit 宽窄屏菜单四组通过，Safari 键盘按其默认 Alt+Tab 导航。

Xcode 26.3 已编译全部选择器代码并在独立 iOS 26.2 模拟器安装启动。运行时与 SDK 资产版本不同，模拟器构建副本暂不编译 AppIcon 目录，产品项目没有因此修改。这不代表正式 iPhone 包或原生选择器完整交互已经验证。模拟器自动操作工具存在窗口坐标错误，选择、取消、再次打开仍需取得实际证据；辅助函数往返测试也不能替代三端原生客户端解析验证。最终候选证据单独保存在 `.tmp/v217-preflight-20261030/`，不提交临时材料。

## 影响

2026-10-30 真机补验使用独立 Test 2.1.7/build 40，正式 App 与 43 项既有偏好保持不变。用户实际看到「从本机上传、引用宿主机项目文件」，前者打开 iOS 系统菜单；用户确认功能正常，并明确接受保留系统菜单中的拍摄选项。这是系统选择入口的验收，不是专用三项菜单已生效的证据。Claude 恢复用户配置的 API 后，测试聊天保存原生 `@` 引用并返回正确首行及唯一测试标记，先前 401 限制已解除；没有修改凭据或原生安装包。

变化限于项目引用的客户端适配与 iOS 附件菜单生命周期，不增加后台请求、连接轮询或文件副本。不改变原生 Codex 普通 Markdown 附件交给默认编辑器打开的已知边界，不修改任何原生客户端安装包。
