# Agent Note: Android 更新下载与安装交接

Status: implemented

## 问题

PR #32 把 Android 更新从浏览器下载改为 App 内下载并调用系统安装器。下载完成、离开 Activity 授予安装权限、返回 App、取消安装和保存 APK 之间需要保留同一个已校验文件，避免重复打开安装器或丢失任务。GitHub 不可达时，用户还需要明确的重试和版本页入口。

## 决策

- 下载仍复用 `ArtifactDownload.Task`。直接访问 GitHub 的更新请求只接受本项目固定 Release 资产地址与 GitHub HTTPS 重定向白名单，且不携带网关 Cookie。大小和 SHA-256 必须有效，完整校验通过后才能安装。后续增加的网关来源遵循 [网关协助更新记录](../feature/2026-10-12-gateway-assisted-android-update.md)，安装交接约束继续适用。
- `UpdateInstallSession` 把已完成 APK 和安装权限交接状态保存在 App 私有目录。恢复及安装前重新校验文件；生命周期中断不代表文件损坏。下载完成事件只自动交接一次，用户取消安装后由「安装」按钮重试。
- `DownloadProvider` 完整复制后原子发布只读副本；发现旧副本长度不符时重新复制。系统保存器的返回结果等待原任务恢复，防止 Activity 重建后失去保存对象。
- 「保存」导出 APK，「安装」调用系统安装器。检查失败时提供 GitHub 版本页入口；下载失败卡片的「GitHub ↗」入口则在外部浏览器打开已检测到版本的 APK 直链，详见 [下载方式选择记录](../feature/2026-10-12-android-update-download-choice.md)。这些入口不能绕过网络对 GitHub 的限制。
- 重复更新演练使用 `.tmp/` 内的源码副本和独立 App 标识。局域网元数据、测试版本、同版本重装只存在于该副本；正式源码的版本选择仍严格要求更新版本。

## 备选方案

- **保留浏览器下载作为主流程**：实现简单，也方便用户使用浏览器的网络环境。但不能满足此次 App 内下载并直接安装的目标，因此仅作为失败兜底。
- **仅在 Activity 内保留安装对象**：没有落盘格式或恢复校验成本。但系统权限页和文件选择器可能触发 Activity 重建，导致文件已下载却无法继续操作，因此只将已完成文件及必要交接状态持久化。
- **正式源码提供任意更新服务器或强制更新开关**：测试方便，但会增加生产更新的信任入口。本次只在忽略提交的源码副本中替换测试输入。

## 测试

`scripts/test-mobile-downloads.py` 覆盖更新元数据缺失、摘要和大小不一致、重定向白名单、凭据隔离、重复交接、权限状态恢复、文件篡改及恢复被中断后的重试。原有普通附件下载和续传用例继续运行。Android 构建及隔离模拟器验证记录保存在 `.tmp/pr32-local/`；用户已报告实测通过，并授权仅合并源码。

## 影响

已完成更新可以跨 Activity/进程恢复，用户仍控制系统安装。代价是维护少量私有状态并在恢复、安装时重新读取 APK 校验；下载中的跨进程续传不属于本次范围。版本已安装或用户关闭任务时清理待安装文件。

历史决策检索未发现已有 `.agents/notes/`、`docs/adr/` 或 `docs/decisions/` 对此交接的记录；手机安装说明位于 [mobile/README.md](../../../../mobile/README.md)，无既有决定需要替代。
