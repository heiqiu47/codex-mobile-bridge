# Agent Note: 浏览器回归与显式模块依赖检查

Status: implemented

## 问题

现有源码测试和操作系统打包检查已具备，但浏览器夹具仍需手动调用。脚本加载容易被误认为检查已执行。功能层和客户端层的反向依赖、跨 provider 导入缺少统一检查。原生手机编译尚未成为常规 PR 检查。

## 决策

Playwright 在 Chromium 和 WebKit 的宽、窄视口中，以生产资源运行现有回环夹具。不复用既有服务；阻止访问夹具 origin 之外的浏览器请求。每项检查都实际调用并等待完成。失败截图、追踪及 JSON 结果在本地保留于 `.tmp/browser-results`，在 CI 中作为失败产物保存。

v2.1.6 WebKit 的失败脚本 URL 缓存是与 PR #88 相关的已知基线问题。只有匹配已观察到的资源错误特征、服务端单次请求、无运行时错误且应用脚本未执行时，才记为预期失败。报告将这些已知失败与功能通过分开。其他失败仍直接使检查失败；页面恢复后运行全部正常断言。本决定记录既有限制，不修改产品或纳入无关 PR。

上段记录门禁首次引入时的基线处理。后续本地纳入 PR #88 后，[启动错误归属与缓存重试决定](../bug-fix/2026-10-27-startup-error-attribution-and-cache-retry.md)取消该预期失败豁免，并增加对应场景的正常通过要求；其他测试和依赖规则不变。下文的首次验收数字仍保留其原始范围。

AST 检查在不导入应用的情况下分析直接、相对及字符串字面量动态导入。平台层不能导入应用、HTTP、功能或客户端策略。功能/客户端模块不能新增上层依赖，provider 不能新增相互依赖。22 条既有符号级依赖逐文件列出例外及原因。失效例外与新增违规都会失败。变量拼接的导入仍由审查负责；新进程中的操作系统选择器测试继续检查运行时加载。

移动检查使用精确 Git 提交，包含删除和重命名路径。Android 使用既有 APK 构建器、CI 本地 JDK/SDK 链接及校验值锁定的 ZXing jar。iOS 使用既有无签名工作流。必需的 `desktop-tests` 作业以 `always()` 显式检查结果，防止被选中构建失败后变成成功跳过的依赖。不涉及签名秘密或生产部署。

产品源码、样式、公开路由和存储格式不变。本地源码整理保留独立 main 和私有恢复归档。活跃数据/工具路径原位保留，避免中断运行中的 App。

## 既有决定

[启动恢复决定](../bug-fix/2026-10-22-startup-resource-recovery.md)部分重叠：行为不变，本决定增加常规浏览器检查执行。[账号展示修正](../bug-fix/2026-10-26-account-ui-and-platform-scope.md)不变；测试验证真实标签、模型选择和布局。其他现有架构笔记涉及运行时 provider/WSL 路由，不被静态依赖策略替代。

## 备选方案

- 手动浏览器检查不需依赖和下载，但不能可靠防止遗漏检查，或只加载脚本而不调用断言。
- 仅用 Electron/Chromium 可复用现有依赖，却遗漏与手机用户相关的 WebKit DOM/布局差异。Playwright 覆盖两类引擎，代价是 CI 下载及运行时间。
- 立即移除全部跨层导入可清理依赖图，却会在添加测试的同时改变持久化、校验和生命周期归属。精确既有依赖例外阻止增长，不将任务扩大为产品重构。
- 迁移私有运行目录可使布局更整洁，但 App 和模拟器正持有这些路径。源码整理保持其稳定，数据迁移作为独立操作。

## 影响

模块依赖违规与重要浏览器回归已有可执行检查。原生构建失败汇入现有必需检查，不新增依赖路径的必需状态。CI 耗时增加，并需要浏览器/SDK 下载。22 条例外仍是技术债，不能证明所有模块已独立。合成响应和无签名构建不替代真机剪贴板、通知、权限、签名或安装检查。

### v2.1.7 Test 三平台验收中的夹具隔离

2026-10-28，`74aecb7` 的 Ubuntu 全量回归发现通知合成用例通过 `_model_identity()` 读取真实 Claude 安装与账号。该测试已模拟桌面协议，却未隔离新增的账号身份路径；本机安装和登录状态因此左右测试结果。用例现在提供临时数据目录及固定合成账号身份，仍走实际 manager、adapter 和通知投递链路，不跳过 Claude 完成事件断言，也不读取真实账号。

PTY 关闭用例原来在 shell/PTY 的 `done` 信号后立即检查子进程。Ubuntu 全量运行出现过一次仍存活的瞬时观测；单独复现及 20 次子进程时序探测均正常结束，尚无证据证明有持续遗留进程。测试现在单独等待子进程消失或进入僵尸态，最多 5 秒，超时仍失败。该修改承认 shell 和子进程异步退出，不改产品停止实现。

继续依赖开发机的真实安装可以少配置一个夹具，但会在无 Claude 的系统稳定失败，且触及真实账号；因此采用显式合成身份。对 PTY 采用跳过断言或无条件固定等待都不能验证退出，故保留有界状态等待。此次仅修改测试，产品逻辑、UI、运行时配置和依赖不变；具体三平台结果在本轮验收记录中分别报告，不将初次失败抹去。


Windows 运行还发现远程创建夹具遗漏 `RemoteStore.list` 模拟，项目列表合并因此向合成别名 `test` 发起实际 SSH。现补齐该只读历史入口，避免合成测试离开回环/模拟边界。原生退出夹具的取消标记使用同步 IPC 确认写入，再让菜单展开继续；正常退出允许助手先返回保守的 `submitted`，但必须另行验证夹具进程在有界时间内真正以零码退出，且此前不得触发夹具清理或强制终止。测试不再将“助手三秒内未见退出”直接等同于“应用不能正常退出”。

本轮临时续跑器曾缺少 Windows 多进程入口保护，并在用例修改自身 `id` 属性后记账失败；其结果不作为最终全量通过依据。修正夹具后重新启动仓库标准 `scripts/test-backend.py`；Windows 此次运行达到 1200 秒时限，保留已完成用例的逐项结果，再由修正后的临时续跑器执行其余用例并核对唯一测试身份，不能将组合覆盖描述为单次标准运行全部通过。原日志保留供追溯。产品资源收尾修正另见[HTTP 收尾](../bug-fix/2026-10-26-proxy-http-backlog-framing.md)和[手动插件绑定](../feature/2026-10-28-dsh-generic-plugin-binding.md)，不能把这些产品修正归为纯测试变更。
